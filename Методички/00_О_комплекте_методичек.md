# Комплект методических указаний к лабораторному практикуму. Блок 1

**Состав блока:** шесть лабораторных работ, 24 часа. Сквозная задача — мультиагентная система планирования курьерской доставки. Каждая работа развивает код предыдущей.

## 1. Состав комплекта

| Работа | Тема | Что появляется в системе |
|---|---|---|
| ЛР-1 | Акторы и акторные системы | Акторная система, обмен сообщениями, порождение акторов |
| ЛР-2 | Каркас МАС: от актора к агенту | Типизированные сообщения, базовый агент, подписка на события |
| ЛР-3 | Простейшее решение задачи планирования | Сцена, сущности, агенты заказов и курьеров, протокол переговоров |
| ЛР-4 | Матчинг, критерии и линейная свёртка | Ограничения, нормировка КПЭ, многокритериальный выбор, JIT-вариант |
| ЛР-5 | Выявление и разрешение конфликтов | Вытеснение размещённого заказа, перепланирование вытесненного |
| ЛР-6 | Адаптивное планирование по событиям | Событийный режим, реакция на появление и выбытие ресурсов |

Нумерация двойная: «ЛР-N (занятие N пособия)» — работы соответствуют главам учебно-методического пособия Д. Е. Новичкова и др. «Разработка мультиагентных систем для управления мобильными ресурсами на языке программирования Python» (СамГТУ, 2024).

## 2. Требования к рабочему месту

Python 3.10 или новее, IDE (PyCharm CE или VS Code), доступ в интернет для установки библиотек. Библиотеки: `thespian`, `pandas`, `openpyxl`. Оперативная память от 8 Гб, свободное место на диске от 10 Гб.

## 3. Эталонный код

Репозиторий `mas_learning_project`, история линейная, один коммит на занятие: `c172d15` — занятие 1, `8565501` — занятие 2, `f912be4` — занятие 3, `07f5fa8` — занятие 4, `2e6813e` — занятие 5, `544a574` — занятие 6.

Эталон предназначен для сверки **после** самостоятельного выполнения работы, а не вместо него. Полезный приём при разборе на занятии — `git diff` между соседними коммитами: он показывает ровно то, что должно было добавиться за занятие.

## 4. Порядок сдачи

Каждая работа защищается индивидуально. К защите предъявляются: работающий проект, результаты прогонов, выполненное задание для самостоятельной работы, ответы на контрольные вопросы. Критерии оценки приведены в каждой методичке отдельным разделом.

Проект рекомендуется вести в собственном git-репозитории с отдельным коммитом на каждую работу — история будет учитываться при итоговой аттестации.

## 5. Сборка документов

Исходники методичек — файлы `.md` в этом каталоге, они являются источником истины. Версии в формате Word собираются скриптом:

```
cd ../04_Сборка
python make_lab_docx.py
```

Скрипт обрабатывает все `.md` каталога и кладёт рядом одноимённые `.docx`. Правки вносятся в Markdown, Word-версия пересобирается — вручную `.docx` не редактируется.
